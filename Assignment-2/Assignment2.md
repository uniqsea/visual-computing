## 2 System Design（系统设计）

### 2.1 Real-time Video Processing Pipeline（实时视频处理管线）

系统的整体实时视频处理管线如图 `[pipeline]` 所示。
 每一帧图像由 OpenCV 从摄像头实时采集，根据所选的处理模式，帧可沿两种不同路径进行：

- 在 **CPU 模式** 下，滤镜处理与仿射变换均在 CPU 上完成，然后将处理结果作为 OpenGL 纹理上传至 GPU；
- 在 **GPU 模式** 下，CPU 仅上传原始帧，而滤镜与仿射变换的计算完全由 GLSL 着色器执行。最终图像通过 OpenGL 以纹理化平面的形式渲染输出。

固定在窗口右侧的 GUI 面板叠加在视频输出之上。当性能评估模块启用时，GUI 会暂时隐藏，以避免其渲染开销影响帧时间测量。

### 2.2 Filters（滤镜模块）

我实现了三种具有代表性的视觉滤镜，用于体现不同的计算复杂度与视觉效果：
 **像素化（Pixelation）**、**漫画风（Comic Art）** 和 **油画风（Oil Painting）**。每种滤镜均提供 OpenCV 实现的 CPU 版本和 GLSL 实现的 GPU 版本，并使用相同的参数配置以保证对比的一致性。

#### **像素化滤镜（Pixelation Filter）**

像素化滤镜是一款计算量小的滤镜，把图像分成大小相同的方块，然后用每个方块的平均颜色去替代该区域的所有像素。
CPU 版本利用 OpenCV 的 `resize()` 函数：先以 `INTER_AREA` 下采样（区域平均），再以 `INTER_NEAREST` 上采样恢复原分辨率。
GPU 版像素化通过把采样位置对齐到每个色块中心，并从匹配blockSize的“低清版图像”取样，来近似实现块内平均。
滤镜包含唯一可调参数 `blockSize`（默认 25，范围 1–50），其语义在 CPU 与 GPU 模式下相同，表示像素块边长。 数值越大，像素化越明显、细节越少。

#### **Comic Art Filter）**

Comic Art 是一种“先压色、再描边”的卡通化滤镜。基本原理是把颜色量化成少量色阶形成大色块，再用边缘检测把轮廓像素染成黑色。在 CPU 端先做 8 级颜色量化，随后用 Sobel 计算边缘强度并按带 gamma 的阈值（edgeThreshold，默认 55，范围 10–100）判定边缘，再对二值边缘做一次 3×3 膨胀以加粗，最后把黑色轮廓叠加到量化色块上；GPU 端在片元着色器中执行同样的颜色量化，对每个像素取 3×3 邻域的最大 Sobel 响应获得类似的加粗效果，应用与 CPU 一致的阈值映射后将边缘像素置黑，从而得到与 CPU 观感一致的漫画化图像。edgeThreshold控制判定为“边缘”的敏感度：数值越大，判定越严格、线条越少；数值越小，线条更多更密。

#### **油画风滤镜（Oil Painting Filter）**

油画滤镜的做法很直观：对每个像素，取它周围一个正方形的小窗口（半径为 Brush Radius），把窗口里的像素按“颜色/亮度”分成少量桶（24 个层级），统计每个桶里像素的数量，然后挑出出现最多的那个桶，把这个桶里所有像素的颜色做一次平均，作为当前像素的新颜色。这样会把细碎纹理“归并”为较大的色块，形成类似笔触的涂抹感。CPU 和 GPU 都用同一套流程：CPU 用循环完成统计与平均，GPU 在片元着色器里并行完成；两端参数语义一致。滤镜只暴露一个参数 Brush Radius（默认 6，范围 1–10），控制邻域大小、也就决定“笔触”的粗细；颜色量化强度固定为 24 级（内部以 uniform 传入，op_radius=radius，op_intensity=24）。由于每个像素都要在局部窗口里做统计，这个滤镜计算量最大，最能体现 CPU 与 GPU 的性能差异。

### 2.3 Affine Transform（仿射变换模块）

仿射变换模块以最常用的三类操作为核心：平移、旋转与统一缩放（sx=sy=s）。

 这些变换由二维仿射矩阵描述：
$$
M =
\begin{bmatrix}
s_x \cos\theta & -s_y \sin\theta & t_x \\
s_x \sin\theta &  s_y \cos\theta & t_y
\end{bmatrix}
$$
其中 `s_x`、`s_y` 为缩放系数，sx=sy=s，`θ` 为旋转角度，`(t_x, t_y)` 表示平移偏移量。

在 CPU 路径中，围绕帧中心构造 2×3 仿射矩阵（旋转角度为 θ、缩放系数为 s、平移以像素计），并用 OpenCV 的 warpAffine（双线性插值，超出区域以黑色填充）对整帧进行重采样。在 GPU 路径中，使用同一组参数生成 4×4 矩阵作为 uniform，顶点着色器对用于显示视频的矩形网格做变换；其中平移会依据实际绘制视口大小将像素量换算为 NDC 坐标，从而保证与 CPU 视觉一致。

鼠标交互与映射采用“像素驱动、像素到NDC一致化”的设计：当启用 Transform 后，左键拖拽直接以屏幕像素为单位更新平移Δx、Δy，右键水平拖拽按“每像素0.01弧度”的比例绕画面中心顺时针/逆时针旋转，滚轮以比例因子1+0.1·yoffset进行统一缩放（数值随后夹到[0.1, 5.0]以保持稳定）。该映射在CPU/GPU两条路径上共享同一组参数并统一围绕帧中心作用，视觉响应一致

### 2.4 Performance Evaluation and Data Logging（性能评估与数据记录模块）

性能评估模块测量两类时间指标：

- **总帧耗时（Frame Time）**；
- **算法执行耗时（Algorithm Time）**。

每次基准测试包含两个阶段：

- **预热阶段（2 秒）**：
   系统在此期间持续处理帧但不记录数据，用于让 GPU 完成着色器编译、缓存填充并稳定管线，
   以消除启动瞬间带来的时序波动；
- **记录阶段（10 秒）**：
   系统逐帧采样帧时间与算法时间，在测试结束后计算平均值。

测试结果会自动以 CSV 格式导出，包含：
 分辨率、滤镜类型、处理模式、是否启用仿射变换、构建模式（Debug / Release）、
 平均帧时、平均算法时、帧率 (FPS) 及样本数量等字段。
 这种结构化记录机制确保实验数据的客观性与可重复性，便于后续统计分析与可视化。

### 2.5 GUI Design（图形界面设计）

系统基于 Dear ImGui 实现交互式图形界面。
 GUI 面板固定在窗口右侧，提供所有运行时控制选项，包括：

- 滤镜选择（Pixelation / Comic Art / Oil Painting）
- 处理模式切换（CPU / GPU）
- 图像分辨率设置（360p / 720p / 1080p）
- 仿射变换启用（旋转、平移、缩放）
- 实时性能统计（帧率、平均帧时、算法耗时）

此外，界面中增加了一个 **“Start Evaluation”** 按钮。点击后，系统会自动执行完整的预热与记录流程，并在结束后生成 CSV 文件。
该设计使性能评估实验可在运行时一键完成，无需修改或重启程序，从而保证实验的可重复性与一致性。
